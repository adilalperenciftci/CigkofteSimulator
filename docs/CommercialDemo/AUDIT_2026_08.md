# Project audit, measured rather than remembered

Taken at master `2c65deb` plus branch `feat/build-mode` (`73f4e26`). Every number
below came from the source or from a run in this session; nothing is carried over
from an older document.

## Method

- Systems: `CreateSystem(` occurrences in `CigkofteGameMode.cpp`.
- Tests: `IMPLEMENT_*AUTOMATION_TEST` macros, counted per file.
- Coverage: `git grep -l <ClassName> Source/CigkofteSimulator/Tests`. Class names,
  not words — an earlier pass searching for "Cat" matched `Category` and
  `Localization` in 34 files and would have reported the cat system as
  well-covered.

## Systems with no test that names them

Measured by class name against the whole `Tests` directory.

| System | Status |
|---|---|
| `CigCatSystem` | **no test** |
| `CigRivalSystem` | **no test** |
| `CigHygieneSystem` | **no test** |
| ~~`CigDeliverySystem`~~ | closed — 6 tests, `CigDeliveryTests.cpp` |

Delivery was the surprise and the one that mattered, so it was closed first.
Deliveries create transient placements, and Stage 3.5 had to carry those across
the layout swap — a defect that branch introduced and caught only because the
*placement* tests covered crates. It now has six tests of its own: the order cap,
the delivery radius, the empty shelf, a successful hand-over, the bulk order's
two-package rule, and the day ending.

Those tests were checked by mutation rather than trusted for passing. Forcing
`NeedPacks` to 1 makes the bulk test fail and names the four assertions that
break — and the first attempt at it crashed the whole run instead, because the
test re-read `Orders[0]` after an attempt that had emptied the array. A test that
takes 220 others down with it on the one run where it is doing its job is worse
than no test, so the door position is now captured once.

Rivals feed pricing, and pricing has 5 tests; hygiene feeds inspection, and
inspection has 4. So both are exercised indirectly through something that does
have tests, and neither is exercised on its own terms. The cat is decorative.

## What a player cannot reach

Not defects — features whose machinery exists and whose door does not:

| Capability | Machinery | Player access |
|---|---|---|
| Rearranging the shop | Stage 3.5, complete and tested | **none** — no build mode |
| Naming the shop | Stage 3.6, complete and tested | F2 on the shop tab, **unverified** |

Both trace to the same missing thing, and `docs/Architecture/BUILD_MODE.md` plans
it. Until it exists, two finished stages are invisible in play.

## Known limitations

25 recorded, across 10 areas: Visual, Verification, Dialogue, Audio, Coverage,
Shop identity, Packaging, Navigation, Platform, Content. The file is maintained

the underlying facts changed, not deleted.

## Severity, as it actually stands

**Blocker: none.** Both packages build, self-test, smoke-test and verify.

**High**
1. **Nobody has played any package.** Not one build has been launched by a person
   in this session or recorded as launched in `QA.md`. Everything known about how
   this game feels is unknown. This is the only item on the list that automation
   cannot reduce.
2. **The input change is unverified.** F2 → type → Enter has never been done. The
   gate's placement is now pinned by a static check after being wrong for three
   commits, but whether focus moves and returns is untested by anything.
3. **No build mode**, which is what makes items in "What a player cannot reach"
   permanent rather than temporary.

**Medium**
4. ~~`CigDeliverySystem` has no test of its own~~ — closed, six tests, verified by
   mutation. See the section above.
5. District pedestrians still get one rectangle; six district interiors are
   unmodelled and a pedestrian there can walk through a stall with collision off.
6. Street furniture has no collision, so the player walks through trees and lamp
   posts. Clearance keeps pedestrians out; nothing keeps the player out.

**Low**
7. `CigRivalSystem`, `CigHygieneSystem` untested on their own terms.
8. `CigCatSystem` untested. Decorative.

**Visual / human-only**
9. Nothing has been looked at: the shop sign at 90 units, the ghost of a moved
   table, whether pedestrians read as people using a pavement.

## The honest summary

The engineering gates are in good order: 221 tests, both configurations packaged
and verified, no unapproved binaries, a navigation authority decided by
measurement, a save schema at version 14 with a migration chain proven end to end
inside the packages.

What the project does not have is a single minute of evidence that it is a good
game, or even a working one in the hands of a player. Every stage since the
consolidation has added machinery and none has been played. That is not a gap
more automation closes — and it is now blocking, because the next three planned
steps are all visual and input-driven, and building them on an unplayed base means
finding out about all of them at once.

**The next thing worth doing is not code.** It is launching
`Build\WindowsDemo\CigkofteSimulator.exe` and playing a day.
